# Android pilot acceptance

Run on an EAS development build, not Expo Go. The browser demo cannot validate native camera, MRZ reading, Supabase session restoration, system authentication, printing, or restart persistence.

1. Configure a staging Supabase project and onboard two shops with the administrator script. Add a staff account to each. Issue administrator-provided one-time login codes and sign in.
2. Complete the shop profile. Create a purchase and a sale with two distinct valid IMEIs; search by either IMEI, phone, name, and ENID number. Reuse a customer, confirm details, and verify older records remain unchanged after editing the customer/shop.
3. Save a draft online, force-stop/reopen, resume it, finalize both transaction directions, and print. Enable airplane mode during editing: saving must fail visibly and keep the current form open. Restore internet and retry; verify exactly one server record even after an interrupted response. Unconfirmed edits have no local persistence.
4. Edit a customer/shop on two devices. The second stale write must show a conflict; refresh and review before retrying. Revoke staff and verify subsequent server reads and writes stop. Drafts must be private to their author, including from other staff in the same shop.
5. Follow [TAZKIRA-SCANNING.md](TAZKIRA-SCANNING.md): capture only the three MRZ lines inside the narrow guide. Verify automatic offline reading, crop-only processing, all check digits, complete 13-digit ID, Latin name, rotation, trim, retake, cancellation and manual fallback. Test glare, tilt, blur, missing edges and Pashto/Dari/English UI with English digits. There must be no front/back wizard or full-card printed reading. Compare consented physical captures, recording only aggregate matches and timing. Optional online MRZ retry must stay hidden until configured and must apply the same checksum checks.
6. Inspect app-private cache after acceptance, cancellation, closing during capture/recognition, background interruption and force-stop/relaunch. Late results must not populate a closed form. Confirm scan-image cleanup and Android backup exclusions. With online reading disabled, no image or raw OCR text may leave the phone. After separately configuring online reading in staging, verify each upload requires explicit confirmation, contains only the selected crop, preserves edits, and respects timeout, cancellation, request deduplication and shared quota limits. Never upload real documents without consent.
7. Deny camera permission, then permanently deny it; the app must offer manual entry and a settings link. Test invalid barcodes, two IMEIs, unknown TACs, duplicate purchase/sale history, and retake/crop/rotation.
8. Compare Pashto and Dari PDF shaping and both buyer/seller mappings to a clear official form. Test long addresses and names, PDF sharing, physical printing, and corrections. Until approved, retain the DRAFT banner and missing-declaration notice.
9. Verify record, customer and draft operations never open or write a local SQLite database. Session credentials remain in secure storage. Sign out and reopen; previous account data must not be exposed. Legacy database files must remain untouched and not be uploaded automatically.
10. Follow the fingerprint matrix in [FINGERPRINTS.md](FINGERPRINTS.md). Enroll three separate impressions plus a fourth verification, add a different optional backup finger, and confirm either finger opens the same customer profile from Home, Customers, and Records. In a transaction, confirm lookup preserves the phone/price and still requires customer confirmation. Test an enrolled customer with no history. Store templates only on Supabase customer profiles or private unfinished drafts; never in finalized records, logs, images or printed forms. Reload online and verify both fingers still match locally. Enrollment is optional without requiring a reason.

Production release gates: source-form verification, consented ENID evaluation, device tests above, connected Supabase integration tests, and owner review of translations. EAS project/signing setup and Supabase deployment remain operator steps.

## Fingerprint USB connection troubleshooting

The connection must be **phone → USB OTG adapter → ZK9500**. A reader attached to the development Mac is not accessible to the Android app; Metro only serves the application code. Keep Metro connected over Wi-Fi while the reader occupies the phone's USB port.

The bundled ZKFingerAndroidSDK 2.1.24 sample supports vendor `1b55`, products `0120` and `0124`; both must be accepted by runtime discovery and the generated USB attachment filter. The scanner screen distinguishes no USB devices, unsupported devices, denied permission, permission timeout, and startup failure. Connection diagnostics expose only USB vendor/product IDs and counts, never serial numbers or fingerprint data. These native changes require a rebuilt APK.

On 2026-10-03, wireless ADB inspection of the Xiaomi confirmed Android enumerated a reader named ZK9500 as `1b55:0124` (6997:292), while the previous installed app accepted only `1b55:0120` (6997:288). This explains the reported reader-not-found error despite a working OTG connection. The replacement APK was installed and launched, and Android's installed USB filter was verified to include both IDs. Physical capture verification is still required.

On hardware, test opening without a reader, attaching it and using **Retry connection**, granting/denying USB permission, unplugging during capture, reconnecting and retrying, and closing while permission is pending. Check that a cancelled attempt cannot enroll or update a closed form, and that retry starts with zero enrollment presses. Confirm actual capture on both enrollment and lookup; a successful APK build alone does not validate the reader.

## Form picture export

Use a fresh development build containing `RecordExport`. From an original record and a correction, tap **Save as picture**, choose a folder, and inspect every PNG. Check Pashto/Dari shaping, two IMEIs, long addresses, both transaction directions, DRAFT labels, signatures and thumbprint spaces against the PDF. Multi-page PDFs produce numbered PNGs at 200 dpi. Test cancelling the folder picker, a read-only/full destination, duplicate filenames, airplane mode, and interruption/restart; temporary files under `form-exports` must be removed. Only explicitly exported completed forms should appear in the selected folder; ENID photos remain private and temporary. Browser export displays a complete 2× PNG in an in-app preview with an explicit download link.
